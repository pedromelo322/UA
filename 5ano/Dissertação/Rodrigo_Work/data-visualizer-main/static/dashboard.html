Vehicle Network Topology
Zonal gateways mirror the physical zones in the testbed, front and rear of the central Vehicle Computer, the HPC (control-plane) node, which is zone 3. Each active zone runs its own flow_monitor and reports into the cluster. Each zone box's dot and top status line reflect flow-monitor liveness; the line below shows that node's live Kubernetes state (Ready condition, kubelet version, allocatable vCPU/memory), polled directly from the cluster API. The HPC box has no flow_monitor of its own, so its dot reflects Kubernetes Ready state directly. Zones come from the NetworkTopology resource: every zone it describes is drawn, including ones with no flow_monitor or node behind them (their boxes say so). Its switches replace the direct zone–HPC lines: the Vehicle Computer's switch (zone 3) sits above the HPC box as the core switch the zonal switches link to, each zonal switch is wired to the zone it serves (labelled with its workload-facing port), switch–switch links are drawn from the resource's links (labelled with the port on each end), and transit-only switches are shown dashed. Each zone's own link gets thicker with its current throughput (on a log scale) and is labelled with it. Boxes list the pods running on that node (hover for each pod). Switch ports a TsnFlow shapes (every hop on its path from talker to listeners) are labelled with the shaper in purple, and those switches get a purple edge (hover for the TsnFlow).
